One result

An ordinary search gamed a shipped judge. A known fix stopped it — on one task.

Best-of-N selection, no jailbreaks, no access to correct answers, run against a documented judge configuration. Two seeds.

Shipped configuration 93 of 96

wrong candidates accepted with a passing score. Every one passed every visible test and failed a held-out test the search never saw.

→
After commit-first judging 0 of 96

The judge solves the task and commits to an answer before it sees a candidate. On this task, that removed the effect completely.

On a second task the same fix made things worse (37 and 41 wrong candidates accepted rose to 50 and 75) because the judge's own committed answer was wrong. That is the paper's main finding: the fix moves the thing that gets gamed from the candidate to the judge — so an evaluator is exactly as good as its judge is at the task, and that is something you can measure before you trust it.

Evaluator review

How an evaluator review works

We are accepting a small number of early evaluator reviews from teams whose scores decide something that matters.

01

Send the configuration

One evaluator — a judge prompt, a rubric, a model-graded harness — the task it scores, and one sentence on what decision its score feeds.

02

We test it the way the paper did

Scored against the open criteria, then an ordinary optimisation loop is run against it: the loop production systems run every day, with no access to correct answers.

03

You get what it accepted that it should not have

Each failure with the evidence — the candidate, the score, the judge's own words — and what to change so the score means something.

Who this is for

Anyone who has to act on an evaluation score.

Product and evaluation teams

Your evaluator gates a release, selects a model or tunes an agent — especially in coding, finance, legal, health and compliance, where a confidently wrong output is expensive.

Assurance, procurement and insurance

You are handed an evaluation score as evidence and need to know what it is evidence of before you accept it.

Framework maintainers

You ship a default judge configuration and would rather hear about it from us than from an incident. Every verdict in the census cites the exact artifact it was read from.
